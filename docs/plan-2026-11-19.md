### 19.1 Wave 1 in detail (the planner's design, read against the code; build in this order)
The planner read the code and found the proof harness itself fails open. These come first, red-first, because
every "N of N bite" this session rested on them:
- **B1** `mutate.mjs --only nosuchthing` selects nothing, prints "killed 0 of 0 mutations (every guard bites)" and exits 0.
- **B2** `runOne` counts any throw from the child as KILLED: a signal, a timeout, an output overflow (1 MB default
  maxBuffer), or a suite that was already red before the mutation.
- **B3** prove's `mutations` row passes on exit 0 and the last line; it never checks that all listed mutations ran.
- **B4** tests reach across files (realised imports orders; ab-test reads RUNBOOK.md; worth-it reads a desk JSON),
  so "changed files only" must follow imports and data files, or it will skip guards that a change can break.
- **B5** this repo's remote default branch is the shared work branch, so a worktree cut from it misses unpushed
  commits; worktrees use `worktree.baseRef: "head"`, and the fixer checks `git merge-base --is-ancestor <base> HEAD`.
- Also: claude-setup's own two mutations run in neither `npm test` nor prove; fold them into MUTATIONS.

**Step 0, save the session's best asset before it vanishes.** The verifiers' realistic-data fixtures (verify5, 6, 7
in the scratchpad) die with this container. Copy them into `scripts/corpus/clean/` (deduplicated by sha256, about
30 files), check they hold no real data (only example.com addresses, no handles or phone numbers; confirm the
product names such as "Harbour Hoodie" are invented, not the studio's real catalogue), run the full prove, commit.

**Step 1, `galxe-desk/scripts/mutate.mjs` (+ new `mutate.test.mjs`, judged by its own suite so the 97 desk mutations
do not pay for it).** Fix B1 (a term selecting nothing exits 1) and B2 (`classify`: KILLED only for exit 1 with
"# fail N>0"; exit 0 is SURVIVED; TIMEOUT and CRASHED are never kills; a baseline run per suite first, and a red
baseline makes every mutation of that suite BASELINE_RED). Add `--jobs N` (1 to 16, default min(4, CPUs); async
pool; results stored by list position so output order is stable; any empty slot fails the run) and `--only a,b`.
Done when `--jobs 1` and `--jobs 4` give byte-identical verbose output and the full prove passes.

**Step 2, `--since <rev>` and `--add <file.json> --group "<line>"`.** `--since`: the rev must verify; changed =
`git diff --name-only -z --no-renames <rev>` plus untracked files; a mutation is selected when its file, its
directory's tests, anything they import (an import graph over the suite folders), a data file under the same
top-level folder, or a listed read file changed; a changed mutate.mjs selects only the lines it added. Any git
failure exits 1; it is never "nothing changed". `--add` (chosen over a paste-printing `--check`, because the paste
was the cost): refuses a batch with a `from` found 0 or 2+ times, `from === to`, a taken name, a missing or
suiteless path, or a newline in the group; then runs the batch and writes nothing unless every line is KILLED; then
writes one group before the closing bracket by slicing (never `.replace`), via a temp file and rename, re-imports and
checks the list ends with the batch, restoring the old bytes otherwise. Steps 1 and 2's own mutation lines go in
through `--add` itself.

**Step 3, `prove --fast` (+ `npm run prove:fast`).** Every check as today, except `mutations`, which runs `--since`
the upstream (else HEAD~1; neither fails closed) and reports as a NOTE ("since origin/<b>: killed 12 of 12 selected,
501 not run"); the last line reads "FAST CHECK ONLY …"; the word PROVEN never appears in fast output. The full prove
is unchanged except B3: its `mutations` row also requires killed N of N with N equal to the list's length.

**Step 4, the guard: `.claude/hooks/guard.mjs` (+ `guard.test.mjs`, about 60 cases).** A PreToolUse hook on every
Bash call (no `if` filter, which would miss `cd x && rm -rf y`), run as `node … || exit 2` so a crash blocks; it
tokenises the command (quotes, `&&`, `;`, `|`, `$( )`, backticks, `bash -c`; heredoc bodies are data) and denies:
force pushes in every spelling (including `+refspec`, `:branch`, `--mirror`, `--delete`); `reset --hard`;
`clean -f` in any spelling; history rewrites (`rebase` except `--abort`, `commit --amend`, `filter-branch`,
`filter-repo`, `update-ref`, `branch -f/-M`); recursive `rm` outside /tmp (never /tmp itself or a session folder's
ancestors; `$`, globs and `~` count as unknown and are denied). It allows everything this session needs (push -u,
heredoc commits that mention force pushes, `pull --rebase`, `merge --ff-only`, `cherry-pick`, worktree add and
prune, `git archive | tar`, `rm -rf` of a literal scratch path). Backed by `permissions.deny` rules in
`.claude/settings.json` as a second layer, plus `worktree.baseRef: "head"`. Live probe: `git clean -f -n` must be
denied in the main session and inside a one-agent workflow (this tests whether subagents' Bash calls are covered).

**Step 5, the owner-data corpus: `scripts/corpus/`** (`clean/` literal files that must pass both scanners;
`caught.mjs` recipes that build the positives at runtime, so no secret-shaped text ever sits in the repo;
`KNOWN_MISSES`, the misses recorded in round 3, asserted still missed so the gap is written in code; a loader that
fails closed on a missing folder, a count below its floor, a binary file, an unknown extension, an email outside
example.com/.org/.net, a handle or a phone number). Every future verifier's new owner-shaped inputs land in
`<sb>/corpus-proposals/` and the lead moves them in.

**Step 6, the two saved workflows: `.claude/workflows/fix-verify.js` and `review-3x.js`** (+ `scripts/workflows.test.mjs`
run in a vm with stubbed agent and pipeline). fix-verify: throws before any agent on missing args or a file shared by
two targets; stage 0 is a cheap read-only premise agent (the tree is clean, HEAD is the base, each finding still
reproduces); each target's fixer works in its own worktree with a schema (changed files, red tests with evidence,
mutation lines as data, refuted findings, branch and head); its verifier works read-only on a `git archive` of that
head, with at least three owner-shaped inputs of its own, and returns holds, problems and evidence; VERIFIED only
when holds is true and problems is empty; **at most 2 rounds per target, then it returns to the lead** (skills.md
TAWAKKUL: improve once, do not over-loop). The lead merges with `merge --ff-only` then `cherry-pick` (files are
disjoint by construction), runs `mutate --add` once, runs the full prove, commits and pushes. review-3x: the three
held-apart lenses (proof, adversary, Leif), two refuters per finding; confirmed only when both returned and neither
refuted; a dead refuter makes a finding unverified (re-run it), never refuted. Both scripts are deterministic, so a
worker restart resumes from the journal. **The big ask's refutation pass is review-3x's first live run, over the
diff of steps 1 to 5** (reviewing built code finds real defects; reviewing a design mostly finds opinions), and
fix-verify then fixes whatever it confirms.

**Assumptions not yet verified, each tested during the build:** that `worktree.baseRef: "head"` applies to a
workflow's `isolation: 'worktree'`; that cloud sessions see `.claude/workflows/` by name (the `scriptPath` call works
either way); that PreToolUse hooks and deny rules cover workflow subagents' Bash calls (the step 4 probe); that four
jobs give close to 4x (node --test also runs files in parallel; measured, and the default chosen from the numbers).
